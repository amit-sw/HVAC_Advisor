Meet the Cast

Every app is a team effort. Here are the five key players in this HVAC advisor and what each one is responsible for.

Five Players, One Goal

Think of this app like a consulting firm. Each department has a specialty, and they pass work between each other to produce a final report. Nobody does everything alone.

⚙
Config Manager

Loads API keys, model names, and settings. The office manager who makes sure everyone has the credentials they need before work begins.

🌡
Climate Engine

Given a city name, finds its coordinates, pulls 10 years of weather data, and translates it into HVAC-relevant notes like "hot summers, freeze risk in winter."

🔍
Document Search

Searches an OpenAI vector store of HVAC product manuals and returns the most relevant chunks with relevance scores.

🤖
Answer Modes (Baseline / RAG / Agent)

Three different strategies for turning your question into an answer. Each one uses the other players differently — or not at all.

🖥
UI & Renderer

The IPython widgets interface: a dropdown to pick the mode, a text box for your query, and rich output that shows evidence, climate profiles, and agent step traces.

Under the Hood: Config Manager

Everything starts with credentials. Here's how the app loads its settings — notice the fallback pattern that checks multiple sources:

CODE 
def get_secret(name: str, default: str = "") -> str:
    if os.getenv(name):
        return os.getenv(name)
    if userdata is not None:
        try:
            value = userdata.get(name)
            if value:
                return value
        except Exception:
            pass
    return default
PLAIN ENGLISH

Define a helper that looks up a secret value by name.

First, check if it's set as an environment variable on the computer.

If found there, use it immediately.

If not, check if we're running in Google Colab...

...and try to read from Colab's built-in secrets manager.

Look up the secret by name in Colab.

If we got a value, use it.

Return the Colab value.

If anything goes wrong with Colab secrets, just move on.

Silently skip — no crash, just try the next option.

If nothing worked, return a default value (usually empty).

💡
Defensive Fallbacks

This "try here, then there, then give up gracefully" pattern is everywhere in professional code. It's called a fallback chain. When you're directing an AI to write code that loads configuration, asking for fallback behavior makes it much more robust.
